## Implemented and checked

The standalone helper starts life at 2 and permits exactly one additional flash. Each tick decrements life; an extra flash occurs when negative life is below a newly sampled negative uniform integer in [0,9], resets life to 1 and chooses a fresh geometry seed. It removes after the second flash. Sound occurs on the initial tick only. Sky illumination is requested for each tick with nonnegative remaining life; the caller sets its sky-flash countdown to 2. Entity effects are requested only on the authority. Hit geometry is x/z ±3 and y −3 through +9, intersected with entity bounding boxes. Initial fire permission requires server authority, difficulty >=2 and loaded radius-10 neighborhood; repeated-flash fire requires server authority and loaded neighborhood without the initial difficulty gate. Individual fire locations additionally require tracking, air and successful fire-placement validation.

`tests/weather_lightning.cpp` checks both shortest and longest delay, exactly one extra flash, seed replacement, sound count, removal, client authority separation, difficulty/loading/tracking gates and hit-box exclusions. These tests do not prove world wiring, visuals, transformations or network synchronization.

## Integration contract

Store transient bolts separately from ordinary mobs; never persist them or permit client-originated creation. Spawn at precipitation height only in raining columns during a storm, with a 1-in-100000 trial per active loaded chunk per tick (the reference debug setting can change that probability to 1-in-100). Select chunk-local x/z from the server's weather random sequence. Spawn packet and reflash packet must carry a monotonically unique strike ID, position, seed and lifecycle state; the client must require the connected server GUID and reject non-finite/out-of-range coordinates and invalid life/flash counts. Deduplicate IDs so retransmission cannot replay thunder audio. Authoritative snapshots on the additional flash avoid independently randomized client timing. This network strategy is a deliberate synchronization adaptation, not an observed reference packet layout.

On creation, attempt fire at the strike coordinate plus four randomly offset coordinates in [-1,1] on each axis, under the initial permission gate. On additional flash attempt the center only under the repeated-flash permission gate. The tracking equivalent must use already loaded, synchronizable chunks, without creating chunks merely for lightning. If the TCPE fire block is absent or a placement check fails, skip it rather than placing an incorrect tile.

On every active authority tick, enumerate intersecting entities and apply the reference base effect: `burn(5)`, increment `onFire`, and if it becomes zero set fire duration to 160 ticks. Pig overrides the base effect: replace with PigZombie at identical position/rotation and remove the pig, server only. Creeper invokes the base effect then becomes powered. TCPE currently lacks a native thunder-hit interface; these hooks must be integrated explicitly. Do not assume ordinary `hurt` damage matches `burn`, which honors fire immunity. Villager-to-witch is not established by this inspected reference and must not be invented for a fidelity claim.

Sound settings in the reference: thunder volume 10000, pitch [0.8,1.0); explosion volume 2, pitch [0.5,0.7). Its sound engine separately limits audible gain, so do not feed volume 10000 directly into a mobile mixer. Distance admission and gain attenuation need separate handling and listening tests. Seeded geometry, sky flashes and the sound engine remain pending integration and visual/audio verification.

## Integrated development runtime and evidence

`WeatherLightningRuntime.cpp` is now wired into native Level weather ticks and already-loaded active chunk simulation. Ecology executes once per eligible loaded chunk before terrain access. Lightning lives in a transient per-Level collection, never in the ordinary mob decoder. Its appended reliable ordered packet carries strike ID, position, lifecycle and full 64-bit seed. The client handler requires the connected server GUID; there is no server-side handler granting clients strike creation. Spawn/reflash/removal broadcasts are generated by the authority. Client event application deduplicates initial sounds and refuses coordinate changes and repeated reflashes for the same strike. Rendering is a separate GLES3 helper using one batched untextured additive mesh and no copied texture. Seeded geometry uses the observed Java-compatible 48-bit random process, four shells, three branches and 16-block vertical segments. The event lasts only through the initial and additional flash, with clients awaiting authoritative reflash timing.

Native entity integration supplies a public base thunder-hit operation with existing fire-immunity behavior, server-only Pig-to-PigZombie replacement and synchronized/persisted Creeper powered metadata. Powered Creepers double the existing TCPE explosion radius; this preserves TCPE's original base explosion scale. The charged texture overlay is not implemented: a suitable authorized texture has not been established in the current assets, so the existing renderer is preserved rather than displaying a missing texture.

Evidence:

- `tests/weather_lightning.cpp` / `work/weather-tests/lightning.log`: lifecycle extrema, authority/fire gates, immutable seeded geometry with 224 quads and finite coordinates.
- `tests/weather_lightning_packet.cpp` / `work/weather-tests/lightning-packet.log`: actual RakNet codec roundtrip including high-bit 64-bit seed, non-finite coordinates, invalid state/phase and truncated input rejection.
- `tests/weather_lightning_world.cpp` / `work/weather-tests/lightning-world.log`: actual isolated Level fire placement, damage/immunity and hit-box exclusion, 160-tick fire transition, PigZombie replacement with pose, Creeper power save/load, exactly one additional flash and one initial thunder/explosion sound event, spawn/reflash/removal broadcasts, client deduplication/no damage, ceiling/client spawn refusal and no neighboring chunk generation. Reproduction helper is `work/build-weather-lightning-test.py`; it compiles the fixture and changed units and relinks existing dedicated objects. No running game or TCSMP was interrupted.
- Host GLES3 syntax checks passed for runtime, Entity, Creeper, packet factory, client handler, Level and renderer. UBSan could not link because the installed runtime is missing; no sanitizer pass is claimed.

Remaining fidelity limits: TCPE's world random source and local x/z selection currently differ from the reference's weather LCG, so identical world seeds do not guarantee identical strike schedules/positions. The tracking gate conservatively uses loaded chunks within four chunks of an active player, rather than claiming equivalence to 4J's player tracking implementation. Geometry has deterministic policy tests but no rendered pixel comparison. Full network source-spoof tests, two-window bolt/audio comparisons, charged texture rendering, audio gain/distance listening tests and phone frame-cost measurements remain pending. These limitations prohibit a complete 1:1 fidelity claim.

## Charged overlay and thunder routing follow-up

The charged texture limitation above is now resolved in development source: the user-supplied Java asset was located and recorded in `POWERED-CREEPER-ASSET.md`. `CreeperRenderer.h` draws the expanded charged shell with additive unlit half-gray shading and 0.01/tick scroll on both texture axes. GLES3Compat already passes the texture-coordinate matrix into `uTX` in its vertex shader. Syntax checks pass; a rendered reference comparison remains pending.

Audio inspection found an actual missing route: the legacy native sound table and the Android `tcpe:` alias table do not define `ambient.weather.thunder`. The existing Java sound bank does define `minecraft:entity.lightning_bolt.thunder`. `LevelRenderer::playSound` now routes this one native event through that existing bank after its normal sound-distance admission; `random.explode` keeps the native path. `tests/weather_lightning_audio.cpp` decodes all selected thunder and legacy explosion samples to valid mono PCM and confirms the missing alias (`work/weather-tests/lightning-audio.log`). SoundEngine's bank path clamps mixer gain to [0,1] while calculating distance range separately, so the reference's large thunder admission volume is not sent as raw mixer gain. Actual audible volume/attenuation and simultaneous-client listening checks are still pending.

The actual-world fixture additionally performs 500000 eligible chunk trials with a fixed random seed: storms produce transient strikes in a rain-capable biome and the same trials produce none in desert. It checks NaN spawn rejection before coordinate conversion, immutable event positions and rejection of a previously removed duplicate event ID. These tests remain isolated from the user's game and public server.

## Real transport and client forgery regression

`tests/weather_lightning_network.cpp` hosts an isolated real native
ServerSideNetworkHandler with two RakNet clients. A server-created strike
produces exactly spawn/reflash/end phases (0/1/2) on both clients, with identical
strike IDs, full seeds, coordinates and lifecycle fields. The additional flash
changes seed exactly once. A third client joins after removal and receives no
expired strike replay. A connected malicious client sends valid clear-weather
and fabricated strike packets; the server's authoritative storm targets/timers
and strike collection remain unchanged and neither client receives forged
events. Server callbacks grant no weather authority through those packet types.

Evidence: `work/weather-tests/lightning-network.log`; reproduction helper
`work/build-weather-lightning-network-test.py` compiles fixture-local relevant
units and relinks completed dedicated objects without a whole build. It does
not alter the user's game or TCSMP. This is actual wire transport/security
evidence, not rendered or audible two-client comparison. Unrelated-peer source
spoofing directly against the client GUID handler remains a separate check.

## Actual client source-GUID boundary

`tests/weather_client_source.cpp` invokes the real ClientSideNetworkHandler
weather/lightning methods using unrelated versus configured authoritative GUIDs.
Unrelated snapshots, spawn/reflash/removal events cannot change state or produce
initial sound events. Valid authoritative events are accepted. Invalid, duplicate
and already-retired events do not replay thunder/impact events.

The fixture also admits two distinct real RakNet loopback peers into a receive
transport and routes decoded packets through the actual client handler. Deliberate
transport admission ensures rejection is performed by the source-GUID guard, not
merely by connection refusal. Unrelated clear-weather/spawn/removal packets are
ignored; authority packets update weather/create/remove the bolt. The receiver
transport is deliberately permissive for this hostile-peer test rather than an
ordinary game connection topology. No user's window/device/server is involved.

Evidence: `work/weather-tests/client-source-boundary.log`; reproduction helper
`work/build-weather-client-source-test.py` compiles one fixture and relinks final
Linux client objects without a whole build. Sound assertions count actual Level
sound callbacks after runtime ticks; audible hardware/mixer quality is a separate
physical test. The earlier pending client source-GUID test is now covered.
